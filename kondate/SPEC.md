# 家庭料理献立アプリ（仮）仕様書

現バージョン: **v2.2**

保有食材・ジャンル・調理時間・キーワードから家庭料理の主菜を提案し、材料の過不足を自動判定するアプリ。決まった料理は外部レシピサイトで検索して詳しい作り方を確認できる。ビルド不要のVanilla HTML/CSS/JS（`index.html` / `style.css` / `script.js` / `data.js`）。

--------------------------------
## 1. アプリの目的

- 家庭料理の主菜を、ジャンル・調理時間・保有食材・キーワードから自動提案する。
- 材料チェックは裏で行い、不足があれば「調達必要」、揃っていれば「作れる」と自動判定する。
- アプリ内蔵のレシピはあくまで目安の「簡易レシピ」。本格的なレシピは外部サイト（クックパッド等）に検索リンクを飛ばして任せる（著作権配慮）。

--------------------------------
## 2. 画面構成

### 2.1 トップ画面（選択画面）
1枚のカードに以下をまとめ、主要なモバイル画面サイズで縦スクロールなしに収まるようにしている。

- **キーワード検索**：料理名・特徴の説明文・主要食材のいずれかに文字列を含む料理に絞り込む自由入力欄（`<input type="search">`）。空欄なら絞り込みなし。
- **ジャンル**：和・洋・中・他のチップ（複数選択可、最低1つは選択状態を維持）。
- **調理時間**：10 / 20 / 30 / 45分のチップ（単一選択）。
- **時間優先トグル**：ONで選んだ時間と完全一致する料理だけに絞る。OFFなら「選んだ時間以内」すべてが対象。
- **人数**：1〜6人前のチップ（単一選択）。簡易レシピの材料分量の換算に使う。
- **調達不要のみ表示トグル**：ONで今ある食材だけで作れる（＝調達不要な）料理だけに絞る。いつでもOFFで解除できる。
- **「献立を決める」ボタン**（プライマリボタン、黄色系配色で背景から視認しやすくしている）。
- **「保有食材」ボタン**（保有食材ページへ）。
- **レシピ検索サイト**：外部検索の対象サイトを選ぶチップ（クックパッド／クラシル／DELISH KITCHEN／YouTube／Google／Bing、複数選択可、除外したサイトは検索候補に出てこない）。

### 2.2 保有食材ページ
- カテゴリ別（肉類・卵豆腐・魚介類・野菜（生・冷凍）・乾物缶詰・乳製品）にチェックボックスで食材の有無を管理。
- 調味料は和／洋／中／その他のタブに分かれたチェックボックス。
- チェックの切り替えは即座に`localStorage`へ保存される。
- 「トップへ戻る」ボタンでトップ画面に戻る。

### 2.3 献立候補一覧（結果画面）
- 上部にサマリー（選択中のジャンル・時間条件・人数・キーワード・件数）を表示。
- 上部の「条件を変える」ボタンと下部の「トップへ戻る」ボタンの両方から、候補リストをスクロールせずにいつでも選択画面へ戻れる。
- 「🔀 ランダム」ボタンで、表示中の候補の順番だけをシャッフルできる（フィルタ条件は変えない）。
- 各候補カードには以下を表示：
  - 料理名、ジャンル／調理時間
  - バッジ：「作れる」（緑）／「調達必要」（オレンジ）
  - 特徴を紹介する一言の説明文
  - 「調達必要」の場合は不足材料のリスト
  - 「簡易レシピを見る」ボタン（展開/折りたたみ式）
  - 「作ったよ」ボタン（トグル式）

#### 簡易レシピ展開パネルの内容
1. サイト選択プルダウン＋「GO」ボタン：選んだ1サイトの検索結果を新しいタブで開く。全サイト除外時はプルダウンの代わりに案内文を表示。
2. 材料（選択した人数分に換算した分量付きリスト）
3. 作り方（手順、目安・簡易的な内容）
4. 💡 プロのコツ（1〜2件）
5. メモ欄（自由記述のテキストエリア、入力すると自動保存）

## 3. データ構造（`data.js`）

### 3.1 `INGREDIENT_CATEGORIES`
保有食材ページに表示するカテゴリ定義。`{ key, label, items: [[食材ID, 表示名], ...] }` の配列。

| key | label | 件数 |
|---|---|---|
| meat | 肉類 | 11 |
| egg_tofu | 卵・豆腐 | 4 |
| seafood | 魚介類 | 10 |
| vegetable | 野菜（生・冷凍） | 25 |
| dried_can | 乾物・缶詰 | 20 |
| dairy | 乳製品 | 5 |

### 3.2 `SEASONING_TABS`
調味料タブ定義。形式は`INGREDIENT_CATEGORIES`と同じ。

| key | label | 件数 |
|---|---|---|
| japanese | 和 | 8 |
| western | 洋 | 7 |
| chinese | 中 | 5 |
| other | その他 | 9（コチュジャン・ナンプラー・カレー粉・クミン・パプリカパウダーなど世界の調味料を含む） |

食材キーの総数：**104**（保有食材＋調味料の合計）

### 3.3 `INGREDIENT_SERVING_INFO`
食材ID → 1人前あたりの目安量（`{ amount, unit }`、人数によらず一定の食材は `{ fixed: '少々' }` 等）。簡易レシピの材料分量を人数に応じてスケーリング表示するために使う。

### 3.4 `DISHES`
主菜データベース。**合計200品**（初期セット100品＋郷土料理40品＋海外の国民料理60品）。

| genre | 件数 |
|---|---|
| 和 | 70 |
| 洋 | 45 |
| 中 | 30 |
| 他 | 55 |

各要素の形式：

```js
{
  name: '料理名',
  genre: '和' | '洋' | '中' | '他',
  time: 10 | 20 | 30 | 45,
  description: '料理の特徴を紹介する一言説明',
  need: ['食材ID', ...],   // 必要な食材（調味料込みのフル材料リスト。作れる/調達必要の判定に使う）
  steps: ['手順1', '手順2', ...], // 簡易レシピの作り方（目安）
  tips: ['プロのコツ1', 'プロのコツ2'], // 1〜2件
}
```

### 3.5 `RECIPE_SITES`（`script.js`）
外部レシピ検索先サイトの定義。`{ key, label, urlTemplate }` の配列。`{query}` を検索語に置き換えてリンクを生成する。

| key | label | URLテンプレート |
|---|---|---|
| cookpad | クックパッド | `https://cookpad.com/search/{query}` |
| kurashiru | クラシル | `https://www.kurashiru.com/search?query={query}` |
| delish | DELISH KITCHEN | `https://delishkitchen.tv/search?q={query}` |
| youtube | YouTube | `https://www.youtube.com/results?search_query={query}` |
| google | Google | `https://www.google.com/search?q={query}` |
| bing | Bing | `https://www.bing.com/search?q={query}` |

## 4. ロジック

### 4.1 材料判定ロジック
- **作れる（available）**：`need` の食材がすべて保有食材でON。
- **調達必要（need to buy）**：`need` の中に保有食材がOFFのものが1つ以上ある。不足分（missing）を抽出して表示する。

### 4.2 献立候補の絞り込み順序（`computeCandidates`）
1. 選択中のジャンルでフィルタ
2. 調理時間でフィルタ（時間優先ONなら完全一致、OFFなら選択時間以下）
3. キーワードでフィルタ（料理名／説明文／主要食材のいずれかに部分一致、空なら素通り）
4. 材料判定（作れる／調達必要、不足材料を算出）
5. 「調達不要のみ表示」がONなら`available === true`のみに絞る
6. ソート：作れる→調達必要の順、同条件内は調理時間の短い順、さらに同条件内は料理名の五十音順

除外・履歴によるマンネリ防止フィルタは**廃止済み**（作った料理でも候補から除外されない）。

### 4.3 外部レシピ検索クエリの生成
```
[料理名, 主要食材（最大2つ、need から調味料・とろみ付け・薬味などを除外したもの）, 'レシピ'] を
半角スペースで連結 → encodeURIComponent → URLテンプレートの{query}に埋め込み
```
主要食材を除外する際に取り除くキー：`SEASONING_TABS`の全キー＋`katakuriko`・`flour`・`panko`・`oil`・`garlic`・`ginger`。
造語っぽい料理名（例:「アジアン風豚肉と野菜の炒め物」）が検索エンジンに一塊の語として扱われてヒットしにくい問題への対策として、主要食材のキーワードを付加している。

### 4.4 分量換算ロジック
`formatIngredientAmount(key)` が `INGREDIENT_SERVING_INFO[key].amount × state.servings` を計算し、単位ごとの丸め幅（g/mlは10単位、それ以外は0.5単位、最小値は丸め幅と同じ）で丸めて表示する。`fixed`指定の食材は人数によらず固定表記（例:「少々」）。

## 5. 状態の永続化（`localStorage`）

| キー | 内容 |
|---|---|
| `kondate_ingredients_v1` | 保有食材のON/OFF状態 |
| `kondate_history_v1` | 「作ったよ」履歴（`{ name, date }`の配列） |
| `kondate_memos_v1` | 料理名ごとの自由記述メモ |
| `kondate_excluded_sites_v1` | 検索対象から除外したレシピサイトのキー一覧 |
| `kondate_preferred_site_v1` | 簡易レシピのプルダウンで最後に選んだサイトのキー |

いずれもサーバー・DB不要、ブラウザの`localStorage`のみで完結する。

--------------------------------
## 6. 「作ったよ」機能

- 押すとボタンが緑色になり「✓ 作ったよ」と表示され、履歴に記録される。
- もう一度押すと記録を取り消し、元の見た目（グレー・「作ったよ」）に戻る。
- 記録の有無は候補一覧の絞り込みには一切影響しない（除外されない）。

--------------------------------
## 7. 技術構成・制約

- HTML / CSS / JavaScript のみ。フレームワーク・外部ライブラリ・CDN依存なし。
- データ保存はブラウザの`localStorage`のみ。
- GitHub Pagesで公開（`https://<ユーザー名>.github.io/<リポジトリ名>/kondate/`）。
- 画面右上にバージョンバッジを表示（タップ/ホバーで変更内容をツールチップ表示）。

### 既知の制約
- アプリ内蔵の簡易レシピ（材料分量・作り方・プロのコツ）は生成時に一括で作成した目安の情報であり、実際に調理検証・出典確認はしていない。味の決め手になる分量や手順は目安として扱い、正確な作り方は外部レシピサイトの検索結果を参照することを前提にしている。
- 主要食材の抽出や検索クエリの組み立てはヒューリスティック（機械的なルール）によるもので、完全な精度は保証しない。
